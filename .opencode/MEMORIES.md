# rel — project memories

Order-book market sim. Redot (Godot fork) 26.2 = renderer + UI only; **Haskell (`sim/`) is the single source of truth for all business logic**.

## Architecture

- `sim/` — Haskell package `rel-sim`: `Sim.Engine` (order book: `Side`/`Order`/`Book`/`Trade`, volumes positive by construction via `mkVol`), `Sim.Gen` (seeded splitmix generator; `refPrice own other` = opposite-side-best-first — callers pass own side first), `Sim.TickGen` (tick export, duplicated roll helpers — do NOT share with Sim.Gen, exporting them costs ~40% runSim perf), `Sim.Cli`/`Sim.Csv` (CSV: open,high,low,close,vol — vol = sum of trade volumes), `SimFFI` (foreign-library, C ABI `sim_generate`). QuickCheck suite runs in the nix build (buildPhase).
- tick modes: `--mode tick-trades|tick-steps` (+ `--book-depth N`, default 50 = old GDScript `ob_depth`) writes `<out>.ticks.csv` sidecar next to the candles csv: `c,price,vol` + book-depth `(bp,bv,ap,av)` quads padded with `0.00000,0`; `vol=0` rows are book-only (marker = last row of every candle, exact end-of-candle book). UI: sim panel mode dropdown; chart aggregates ticks to candles and plays the per-candle book snapshot at the replay head (`Series.books`, `OrderBookWidget.set_book`); plain csvs keep the synthetic ladder.
- price ref (2026-10-13, updated): the `opposite` price-ref mode is REMOVED — `RefMode`/`spRefMode`/`--price-ref`/the UI "price ref" dropdown are gone; mid anchoring is the only behavior (`oppositeRef` survives as the one-sided fallback inside the mid chain). Spike history: leftover volume rested up to `tick-range` beyond the OPPOSITE touch, bid/ask stacks did independent random walks, spread never closed (processOrders only matches `bp >= ap`). Mid alone kills spikes (max close-to-close move 0.0035 @20k×500 seed 7, same as with clamp). COST: mid reads both book sides per order — new 100k×1k baseline ≈ 16.7s (old opposite baseline was 11.7s); that +40% is intrinsic to mid, don't chase it in the engine without a bigger refactor. `--clamp-rest on|off` stays (UI checkbox).
- stale sidecar trap (2026-10-13): `chart.gd add_timeline` prefers a `.ticks.csv` sidecar over the candles csv whenever it exists. A same-name regeneration in candles mode used to leave the old tick sidecar behind → chart silently rendered the OLD run (reported as "10× more candles"). Fixed: `SimFFI.writeCsv` ModeCandles removes a pre-existing sidecar (verified headless). Pre-fix stale sidecars in `user://simdata` are still there — delete by hand.
- async UI generation (2026-10-13): `sim_panel.gd` runs `SimNative.generate` on a GDScript `Thread` (GHC auto-binds the foreign pthread on the `foreign export` entry); `_process` polls `progress()` (0..1, per-candle, hits 1.0 during the post-loop CSV write while thread still alive) and `wait_to_finish()` wires the timeline back. Generate button toggles to Cancel → `cancel()`. Engine: `SimHooks` (per-candle progress + cancel poll) in `Sim.Internal`; hooked drivers in SEPARATE modules `Sim.GenH`/`Sim.TickGenH` (full copies, same rationale as Gen↔TickGen). FFI: `sim_progress`/`sim_cancel` exports over NOINLINE IORefs; cancel throws `SimCancelled`, `sim_generate` returns 3 and removes csv/.meta/ticks sidecar. `-threaded` REQUIRED on the foreign-library (non-threaded RTS + worker in `base`'s unsafe `write()` → main-thread `sim_progress` dies with `schedule: re-entered unsafely`).
- tick-mode scale gotchas (2026-10-13): the ticks sidecar is ~2.5MB per 1k candles at 500 ord/candle tick-trades, depth 50 — a 30k-candle run writes a 7.3GB sidecar (minutes of "99%" write-out). Progress reserves the last percent: hook reports done/(total+1), (1,1) only after all files written — without this the UI shows 100% for the whole write-out. Fixed O(n²) tick accumulation: `ts ++ reverse ticks` per candle and `reverse ticks ++ acc` per order both copied growing lists; now chunked (`reverse ticks : tss`, final `concat (reverse tss)`) in TickGen AND TickGenH, output identical. CLI (`app/Main.hs`) uses `runSim` only — tick paths are reachable ONLY via FFI/UI and the QuickCheck suite; CLI timings say nothing about tick-mode perf.
- streaming tick export (2026-10-13): the FFI/UI tick path no longer materializes ticks — `runSimTicksH :: SimHooks -> (Tick -> IO ()) -> SimParams -> IO [Candle]` emits rows through a sink (`Sim.Csv.tickRow`/`tickHeader` exported); SimFFI opens the sidecar with 1MB BlockBuffering and sinks rows during generation. 30k×500 tick-trades: RSS flat 176MB (was multi-GB + swap), output BYTE-IDENTICAL to list-based, cancel mid-stream removes the partial sidecar. Emit order per candle: order-step ticks forward, then end-of-candle marker (list-based export reverses the same batch — verified identical). Row sink is `Sim.Csv.tickRowB` (bytestring Builder): bytestring 0.12 REMOVED doubleFixed, and prices are p/10^scale exactly, so the INTEGER is formatted directly (intDec + zero-padded fraction) — byte-identical to printf "%.5f", ~13x faster (107MB/s vs 8MB/s; 7.7GB sidecar in 100s). Never pkill -f with a pattern that appears in your own command line — zsh -c cmdline matches and the shell kills itself.
- perf pitfall measured 2026-10-13: adding the IO driver (or any large binding) to `Sim.Gen` itself starves GHC's shared simplifier budget and de-specializes the untouched `runSim` (11.7s → 15-16s, chain: runOrders→mkPriceFun→lambda inlining). Duplicating machinery inside the module doesn't help; separate module restores 11.7s bit-identical. `{-# INLINE runOrders #-}` alone gets 12.7s — insufficient.
- book-drain deadlock: when BOTH sides empty, refPrice returns Nothing → market freezes forever (mid mode hit it at seed 1). Fixed via `gsAnchor` (last trade price, init = start mid) used as final refPrice fallback; Gen.TickGen both update it, logic duplicated as usual.
- perf: 100k×1k ≈ 11.7s baseline; clamp/mid modes ≈ 15.8–16s (+35%, opt-in only — per-order Maybe-chain overhead, profiling not worth it). Perf trick: `mkPriceFun` resolves ref-mode/clamp ONCE per run into a specialized `PriceFun` closure — per-order flag checks cost ~40%.
- `gdextension/shim.cpp` — godot-cpp 4.5 shim exposing `SimNative.generate(params, out_path)` + `SimNative.resume(params, out_path)` to GDScript; `hs_init`/`hs_exit` in ELF constructors.
- resume/continue (2026-10-14): every successful FFI generate writes a continuation snapshot `<out-basename>.state` (`Sim.Resume`: full params in CLI key=value format parsed back via `applyArgs`, `done=` candles written so far, SMGen via `show`/`Read` (splitmix Read validates odd gamma), anchor, in-progress candle, `b=`/`a=` book levels). FFI `sim_continue` (shim method `resume` — "continue" is a GDScript keyword) takes ONLY the candle count from the passed params, everything else from the snapshot; appends rows to the candles csv (`csvRowsText`, header only if the file is missing) and streams tick rows with candle indices continuing at `done`. Cancel mid-resume: sidecar truncated back to the pre-run size recorded in a NOINLINE IORef (`hSetFileSize` — base 4.20 REMOVED `hSetSize`), candles csv untouched (appended only after generation completes), state not rewritten; code 4 = no state. `runSimH`/`runSimTicksH` now take a start `GenState` and return the final one; tick driver takes the starting candle index. UI: sim panel "Resume" button continues the timeline named in the form (needs its `.state`); chart `add_timeline` reloads a same-name series in place (colors/indicators kept). Verified headless: 100+50+10 resumed csv byte-identical to a straight 160-candle run; tick resume sidecar grows with continued indices; cancel truncates exactly. Sim.Gen untouched — 100k×1k still ~17.3s, output bit-identical. QuickCheck flakiness FIXED 2026-10-14 in 5987d26 (suite now fails the build on any prop failure, per-prop `== name` banners; see the QuickCheck gotchas bullet) — older build logs may still show random FFT prop failures, ignore those.

Signal handlers must take the signal arg (`_id: int`) — zero-arg connect fails at EMIT time in Redot 26.2 (see gotchas below). Rendering draws every candle inside the visible index window (bounded by screen width, ~1.4k candles/frame max) — no replay-head cap; `view.follow` auto-scrolls the tail to the right edge while playing, re-attaches on new timeline.
- FFT forecast indicator (2026-10-13): `add FFT` button in the RMB menu; window start/end set by dragging the two dashed vertical handle lines on the chart (5px grab tol, per-indicator not per-series, min separation 16; candle-center rounding: start=i−1, end=i of `round(x_to_index)`); start/end/predict/waves via right-aligned SpinBoxes embedded IN the menu (see menu bullet below); index 0 is a VALID concrete start (only end≤0 = follow-tail, start<0 = auto); `locked` mode (menu checkbox): dragging either handle shifts the whole window by the same delta (`_shift_fft_window`, clamps start≥0, width preserved); `edge_w` endpoint-weights the fit (menu `edge w` spin, FFI param) — weighted Gram via closed-form ramps (leftRamp/geo/tgeo, phases WRAPPED before the ramp sums or 2pi multiples hit the sin(c/2) pole — cost one debug cycle) + corrWV. Leverage at the boundary is 2k*w0/sum(w): ramps must be ALMOST POINT-SHAPED (h = max 2 (n div 128)); wide ramps dilute edgeW and even normalization caps the pin at 2k/rampMass. Pins SMOOTH endpoint deviations only (real data: last-candle err 102->27 at edgeW=100); a sharp single-candle edge spike is unmatchable by a smooth basis and heavy weights make it WORSE (Gibbs) — do not chase that case. Gotcha: prop dropped from the props list silently during the named-props refactor (defined-but-unused warning was the only trace) — check the warning when adding props. Math in Haskell `Sim.Fft.fftApprox`: unboxed iterative FFT (top-k padded bins SNAPPED to exact window DFT bins q/n + dedup — snapped columns are exactly orthogonal so the solve provably cannot explode; non-snapped frequencies explode on real data at waves≥40, do NOT revert) + HARD LOW-PASS q ≤ n/8 (shorter-period bins fit per-candle noise — on real candles the spectrum is noise-flat, so without the low-pass top-k picks arbitrary period-2..10 bins and the forecast jumps around then flatlines; with it max jump ≈ 0.3x median candle move) → ridge-LS via closed-form Dirichlet-kernel Gram + Jacobi eigendecomp on STUArray (near-null truncation kept as belt-and-braces) → synthesis by rotation recurrence (unboxed ST). Deps `vector` + `array`. FFI `sim_fft_forecast(closes,count,start,end,predict,waves,out)` writes fit‖forecast, shim `SimNative.fft_forecast(closes,start,end,predict,waves)`. Widget draws in-window fit solid lightened +0.55, forecast dashed; cached on Indicator keyed by (series,start,end,predict,waves,candles.size). Parameter search `fftBest rmsePct predict closes`: walk-forward grid over window ∈ {2,3,4.5,7,11,17}×predict (clamped) × waves ∈ {2,4,8,16,24,32} (capped by window/8 low-pass), anchors extend to len−50 so the evaluated forecast always overlaps real data ≥50 candles (longer forecasts scored on their overlapping head; UI sets end = len−50), anchor step = predict, hybrid score w·relRMSE + (1−w)·(1−dirAcc); `fftForecast` = fit-less forecast for the search. FFI `sim_fft_best(closes,count,predict,rmsePct,out3)`, shim `SimNative.fft_best`; UI: `opt` button + `opt rmse %` spin in the FFT menu row → sets start/end/waves + opt_score (shown in HUD). In-sample only — no forward guarantee. Measured: 100k window waves=50 ≈ 130ms; sim1.csv 0..705 predict=150 waves=40: 1ms, forecast smooth + bounded.
- KS entropy indicator (2026-10-14): "add KS" in the RMB menu, rolling **permutation entropy** (Bandt–Pompe, normalized H/ln m!) as the KS proxy — math in `Sim.Entropy` (`permEntropy`, `rollingPermEntropy`), NOT Lyapunov/K2 (fragile on price data). Ordinal patterns of length m (Lehmer-coded ids, ties broken by index) in a sliding `period`-window; the slide is O(1) per candle because the window's pattern count (win−m+1) is constant, so H = ln T − (Σ c·ln c)/T updates via two bins. m clamped 2..7 (menu spinbox), default 5. Output 0..1, one value per candle, NaN warm-up; widget draws it over the FULL plot height (1 = noise-like, 0 = trending) — it is NOT price-scaled. FFI `sim_perm_entropy(closes,window,m,out)` → shim `SimNative.perm_entropy`. Gotcha: with short windows the estimator can't saturate (win=100/m=5 → ~0.87 max, coupon-collector: E[H]≈ln(occupied bins)) — that's math, not a bug. 100k candles ≈ 0.23s, cached on Indicator keyed by (series,period,m,n). NOTE the shared-cache wart: one `vals` field per indicator, last-drawn series wins — same pre-existing pattern as FFT's fit/forecast.

(2) Never generate test data from raw `arbitrary Int` (|s| up to 9e18 makes 1e-6 tolerances lose to FP summation order) — bound with `mod`. (3) `corr`/`fftApprox`-consuming props must `take n` BEFORE the producer, or an accidental `take n xs ++ repeat v` is an infinite list and `corr` loops forever (suite hangs at -O0/-O1). ## Nix gotchas (all cost a build cycle)

- **Nix builds from the git tree.** Untracked/intent-to-add files are invisible → `can't find source for ...`. Always `git add` before `nix build` / `nix flake check`. `flake.nix` itself must be tracked to evaluate.
- `nix build .#sim-extension` retargets the `./result` symlink away from redot — re-run `nix build .#redot` (cached) or use the store path directly.
- Redot editor scans **every `.gdextension` under `res://`** — never keep template `.gdextension` files in source dirs (it creates `extension_list.cfg` entries). Template lives in `nix/gdextension.nix`.
- Haskell foreign-library on nixpkgs: needs `-fPIC` on the **library stanza**, plus `splitmix` override with `--ghc-options=-fPIC` (`nix/sim.nix`). `options: standalone` does NOT work (nix GHC's static RTS is non-PIC) — link RTS dynamically and fix rpaths with `autoPatchelfHook` in the consumer.
- GHC RTS does not self-init when dlopen'ed — `hs_init` via `__attribute__((constructor))` in the shim, else `newBoundTask: RTS is not initialised`.
- GDExtension is `reloadable = false` ON PURPOSE (nix/gdextension.nix): the shim runs `hs_exit` on unload and the GHC RTS cannot be reinitialized after `hs_exit`. Redot's editor auto-reloads a changed `.so` on focus → wedge: generation completes (CSV on disk) but the worker thread never returns to Godot → panel polls `is_alive()` forever, UI looks frozen, Cancel stays disabled. After `link-sim-extension` a FULL editor restart is required; a days-old editor session silently keeps the stale lib (which is also how "code 1 after relink" happens: old scalar parser still in memory). Verified: fresh-process async generate (thread + progress polling) works headlessly every time.
- nix ''-string pitfall (cost a build cycle): comment lines inserted into the indented heredoc in nix/gdextension.nix must KEEP the block's 4-space indent — unindented lines shift the common-indent dedent, the `EOF` terminator drifts, the heredoc eats the rest of the phase, and the build SUCCEEDS with an empty `bin/`.
- Cabal rejects module + dir name clash (`Sim.Types` file + `Sim.Types/` dir) — internal module is flat `Sim.Internal`.
- `cp` from nix store into project: `rm -f` target first + `chmod u+w` (store perms are read-only).

## GDScript/Redot gotchas

- `:=` inference fails on Variant chains (Dictionary values, untyped node vars) — annotate the var type explicitly.
- Inner classes: access via `const PlotDataScript := preload(...)` then `PlotDataScript.Series.new()`, not via node instance.
- In `SceneTree -s` scripts, `@onready` vars are not set in `_initialize()` — `await process_frame` after `add_child` first.
- `SimNative` GDExtension class only exists after the extension is linked and project imported; `sim_panel.gd` guards with `ClassDB.class_exists`.
- Redot 26.2 signal arity: connecting a 1-arg signal (e.g. `PopupMenu.id_pressed`) to a ZERO-arg method "succeeds" (connect returns OK) but the call fails at emit time with `Method expected 0 argument(s), but called with 1` — printed to console only, UI looks like a dead menu item. Always match the signal's arg count (`func _h(_id: int)`), use `.bind` for extra params. Also: `PopupMenu` has NO `activate_item`/`get_item_rect` methods (probe with `get_method_list()`); `Input.parse_input_event` works headless for testing real click paths.
